# RAG

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Вопрос к источникам: обосновано ли утверждение в [`../../practice_01/tests_load.md`](../../practice_01/tests_load.md), строка «Когда потребуется полноценное нагрузочное тестирование: после инкремента 3...», и не упущена ли связь между тем, что именно добавляет инкремент 3, и уже отклонённым в этой же практике сценарием «SEC-1 под конкуренцией» (см. `few_shot/experiment.md`)?

## Запрос

Инструмент/модель: OpenCode CLI 1.18.30 / anthropic/claude-sonnet-5, отдельный тестовый запуск (инструменты записи запрещены), на вход поданы ровно 4 разрешённых файла выше (без остальных файлов Практики 1). Задача: ответить на 2 вопроса, используя только эти источники и явно указывая файл/строку для каждого факта, либо прямо заявляя «не подтверждено источником» без домысливания.

## Ответ со ссылками на источники

**Вопрос 1: меняет ли инкремент 3 предпосылку отклонения сценария SEC-1?**

`project_management.md`, строка «Инкремент 3»: «Добавлены `SEC-1` (удаление секретов)... AI-агент предлагает реализацию редактора секретов» — то есть инкремент 3 явно добавляет код редактора секретов, которого раньше не было (подтверждено также `context.md`, раздел «Что пока неизвестно»: «в примере `TRAINING_PR.diff` такой логики нет»).

Предпосылка отклонения в `few_shot/experiment.md`, раздел «Что отклонили»: риск «зависит от того, как будет реализован **ещё не написанный** код — то есть не подтверждён строкой diff».

Вывод модели: да, предпосылка «код не написан» после инкремента 3 станет неверной. Важная оговорка (без домысливания): ни один из 4 источников не описывает архитектуру будущего редактора (stateless-функция или разделяемое состояние) — источники подтверждают только появление кода, а не то, что сценарий автоматически станет обоснованным; для этого потребуется повторная проверка по `QA-1` уже на реальном коде.

**Вопрос 2: есть ли в `project_management.md` прямое указание обновить `tests_load.md` по факту завершения инкремента 3?**

Условие в `tests_load.md` — конъюнкция «после инкремента 3 **И** (webhook **ИЛИ** SLA)»; без webhook/SLA полноценное нагрузочное тестирование по формулировке файла не требуется. Колонка «Проверка» для инкремента 3 в `project_management.md` указывает только `tests_unit.md`/`tests_integration.md` — `tests_load.md` там не упомянут.

Вывод модели: **не подтверждено источником**. Ни `project_management.md`, ни `tests_load.md` не содержат прямого указания, что сам факт завершения инкремента 3 (без webhook/SLA) должен обновить таблицу `tests_load.md` или разблокировать отклонённый сценарий `SEC-1`. Связь между инкрементом 3 и предпосылкой отклонения `SEC-1` — это наблюдение по ответу 1, а не зафиксированный ни в одном источнике триггер; модель прямо отказалась выдавать эту связь за подтверждённый факт.

## Что изменили в исходном артефакте

- Файл и раздел: [`../../practice_01/tests_load.md`](../../practice_01/tests_load.md), абзац после таблицы сценариев («Когда потребуется полноценное нагрузочное тестирование...») и раздел «Как использовали AI».
- Изменение: добавлено явное условие пересмотра — после завершения инкремента 3 (появления кода редактора секретов) нужно заново оценить по `QA-1`, обоснован ли отклонённый сценарий «SEC-1 под конкуренцией», в зависимости от того, как редактор хранит состояние (разделяемое vs локальное). Это зафиксировано как решение, добавленное по итогам эксперимента, а не как факт, якобы подтверждённый `project_management.md` (там такой связи нет — см. «Ответ со ссылками» выше).
- Как проверили ссылки: сверил дословно все 3 цитаты (`project_management.md` строка «Инкремент 3», `context.md` раздел «Что пока неизвестно», `few_shot/experiment.md` раздел «Что отклонили») с текущим содержимым файлов; `make step1` проходит.
- Что отклонили как неподтверждённое: любую формулировку вида «после инкремента 3 сценарий SEC-1 автоматически становится обоснованным» — источники подтверждают только появление кода, не его архитектуру и не факт риска; вместо готового вывода в файл добавлено условие «проверить», а не «считать обоснованным».
