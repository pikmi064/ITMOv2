# R.C.T.F.

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- **Role:** инженер по нагрузочному тестированию, применяющий уже согласованный (по итогам few-shot) критерий отбора сценариев к полному списку правил репозитория.
- **Context:** в `tests_load.md` есть критерий: сценарий попадает в файл, только если поведение системы зависит от конкуренции за общий ресурс между параллельными запросами; иначе это integration-тест, повторённый N раз. По этому критерию из файла удалены 2 сценария на `API-1`. Полный список правил — `context.md`, раздел «Факты и правила»: `SEC-1`, `API-1`, `REL-1`, `OUT-1`, `QA-1`, `SCOPE-1`, `OBS-1`.
- **Task:** применить письменный критерий к каждому из семи правил по очереди: (а) есть ли в `TRAINING_PR.diff` код, подтверждающий существование общего ресурса/состояния, за которое могут конкурировать запросы; (б) нужен ли отдельный нагрузочный сценарий для этого правила. Не предлагать сценарии для правил, где в diff нет подтверждающего кода.
- **Format:** одна таблица (`Правило | Есть код общего ресурса? | Нужен сценарий? | Статус в tests_load.md`) + вывод не длиннее 3 предложений.

## Полный запрос

Инструмент/модель: OpenCode CLI 1.18.30 / anthropic/claude-sonnet-5, отдельный тестовый запуск (инструменты записи запрещены), файлы на вход: `tests_load.md`, `context.md`, `TRAINING_PR.diff`.

Первая версия запроса просила модель оценить, оправдан ли отдельный сценарий на `OBS-1`. Модель ответила отказом: в diff нет кода логирования вовсе, добавлять сценарий не за что. Запрос переформулирован на систематическую проверку всех 7 правил `context.md` — текст ниже.

Финальный текст Task/Format — как в блоке Role/Context/Task/Format выше, дословно передан модели.
