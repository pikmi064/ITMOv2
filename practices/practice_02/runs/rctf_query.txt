## Role

Ты — инженер по нагрузочному тестированию, отвечающий за минимальный набор load-сценариев
для первого инкремента ассистента код-ревью PR (эндпоинт POST /api/reviews).

## Context

Файл practices/practice_01/tests_load.md уже содержит критерий отбора сценариев: сценарий
попадает в этот файл, только если поведение системы зависит от конкуренции за общий ресурс
между параллельными запросами (иначе это integration-тест, повторённый N раз). Пример уже
принятого по этому критерию сценария — «Утечка секрета под конкуренцией (SEC-1)»: он опирается
на факт, что app/api.py:3 и app/api.py:8-10 используют один и тот же экземпляр review_service
(singleton) для всех запросов, без per-request изоляции.

Правило OBS-1 из context.md: "в лог пишутся только request_id, длительность и статус;
содержимое diff и ответа модели не логируется". Сейчас OBS-1 проверяется только в одиночных
сценариях: tests_unit.md (один diff с маркером MARKER_UNIQUE_42) и tests_integration.md
(тот же маркер, один запрос). Ни один из них не проверяет, что происходит, когда логирование
идёт от нескольких запросов одновременно через общий logging handler/buffer — а это ровно
такой же тип общего ресурса, как singleton review_service в кейсе SEC-1.

## Task

Реши, оправдан ли отдельный нагрузочный сценарий для OBS-1 по уже сформулированному критерию,
и если да — предложи одну новую строку таблицы для tests_load.md по аналогии со строкой SEC-1:
с конкретным числом параллельных запросов, уникальным маркером на каждый запрос (чтобы отличить
cross-request утечку от собственной), измеримым пределом и evidence с точным file:line из
TRAINING_PR.diff или ссылкой на context.md. Если считаешь, что сценарий не оправдан — явно
аргументируй почему, используя тот же критерий (какой конкретно общий ресурс есть или отсутствует).

## Format

Ответь в одном блоке:
1. Вывод одним предложением: оправдан сценарий или нет.
2. Если оправдан — готовая строка таблицы в формате
   | Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Evidence |
3. Обоснование 3-5 предложениями со ссылкой на конкретный file:line (не общими словами).
Не добавляй разделы сверх этих трёх пунктов, не пересказывай весь diff.
