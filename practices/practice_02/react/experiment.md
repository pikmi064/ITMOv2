# ReAct

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Цель: пошагово проверить, что каждая ссылка `file:line` в [`../../practice_01/tests_load.md`](../../practice_01/tests_load.md) действительно указывает на ту строку [`TRAINING_PR.diff`](../../practice_01/TRAINING_PR.diff), которая утверждается в тексте рядом с этой ссылкой — после 5 предыдущих экспериментов файл накопил много таких ссылок, и ни одна не была сверена построчно одним проходом.
- Доступные входы: `tests_load.md` (полный текст), `TRAINING_PR.diff` (полный текст).
- Разрешённые действия: `grep_diff(pattern)` — поиск по diff; `read_diff_line(N)` — содержимое строки N итогового файла; `compare(ref, claimed)` — сверка утверждения с реальным содержимым; `conclude(verdict)` — вердикт по одной ссылке.
- Запрещённые действия: изменять файлы, использовать источники кроме двух переданных, придумывать содержимое строк без выполнения `read_diff_line`.
- Максимальное число шагов: 12 (по числу найденных ссылок `file:line`, с учётом повторов).
- Условие остановки и вопроса человеку: если после 12 шагов остались непроверенные ссылки — остановиться и перечислить; если вердикт «неоднозначно» — не угадывать, передать решение человеку.

## Запрос

Инструмент/модель: OpenCode CLI 1.18.30 / anthropic/claude-sonnet-5, отдельный тестовый запуск (инструменты записи запрещены), файлы на вход: `tests_load.md`, `TRAINING_PR.diff`. Задача: пройти по каждой ссылке `file:line` в формате Thought/Action/Observation и дать итоговую таблицу «Ссылка | Утверждение | Реальное содержимое | Вердикт».

## Что изменили в исходном артефакте

- Файл и раздел: [`../../practice_01/tests_load.md`](../../practice_01/tests_load.md), вводный абзац (фраза про `API-1`/`len(diff)`) и раздел «Как использовали AI» (уточнение про `app/api.py:3`).
- Изменение: переформулирована фраза «Правило `API-1` (`len(diff)` в `app/api.py:8-10`) синхронное...» → «Правило `API-1` (проверка `len(diff)`, которой в этом diff ещё нет — `app/api.py:8-10` принимает `payload["diff"]`... без валидации длины) в любой корректной реализации будет синхронным...» — убрана формулировка, из которой следовало, что код проверки физически существует в указанных строках. В «Как использовали AI» добавлено уточнение, что `app/api.py:3` подтверждает лишь module-level импорт, а не строго доказывает паттерн singleton.
- Как проверили: пересчитал итоговую нумерацию строк `app/api.py` и `app/review_service.py` после применения `TRAINING_PR.diff` вручную и сверил с выводом модели по каждой из 4 ссылок; `grep -n "len(diff)"` по всему `TRAINING_PR.diff` подтвердил отсутствие паттерна; `make step1` проходит.
- Что отклонили: вердикт «неверная строка» не потребовал отклонения — это была реальная найденная ошибка, исправленная в тексте; по ссылке `app/api.py:3` (singleton) решили не менять вердикт «неоднозначно» на «подтверждено» и не убирать evidence целиком — вместо этого явно ограничили формулировку тем, что доказано (module-level импорт), не выдавая её за полное доказательство singleton-паттерна.
