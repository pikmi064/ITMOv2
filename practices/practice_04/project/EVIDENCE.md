## Runner: синтаксис и логика

Команда: `python3 scripts/check.py` или `make check`.

Сохранённый исходный вывод: [output/checks.txt](output/checks.txt). Он содержит `PASS: Python syntax`, `PASS: JavaScript syntax`, семь результатов `ok`, итог `Ran 7 tests` / `OK` и `PASS: all checks`.

| Проверка | Что подтверждает |
|---|---|
| `test_window_excludes_completed_unscheduled_and_later_tasks` | В выборку не попадают завершённые задачи, задачи без срока и задачи после конца интервала; последняя дата включена |
| `test_zero_includes_today_and_overdue` | При `days=0` возвращаются сегодняшние и просроченные задачи |
| `test_invalid_days` | Отклоняются `-1`, `366`, `true`, дробное число и строка |
| `test_query_does_not_modify_database` | Байты базы не изменяются после запроса |
| `test_missing_database_is_not_created` | Отсутствующая база даёт ошибку и не создаётся автоматически |
| `test_trim_and_validate` | Название и предмет очищаются от пробелов, правильная дата принимается |
| `test_bad_input` | Отклоняются неправильный тип входа, пустое/длинное название, несуществующая дата и неправильный тип предмета |

Тесты используют временные базы; сохранённые задачи пользователя не служат тестовыми данными.

## Собственный MCP

Команда: `make mcp-demo`. Клиент запускает отдельный процесс `mcp_server.py`, выполняет MCP initialize, tools/list и tools/call через stdio. Это не прямой вызов Python-функции.

В [output/mcp-demo.json](output/mcp-demo.json) сохранены:

- `server` и `tools`: ответ инициализации и описание tool;
- `calls[0]`: вход `{"days":7}` и задачи со сроками `2026-10-06` и `2026-10-09`, счётчики 1/1;
- `calls[1]`: вход `{"days":-1}` и ошибка `greater_than_equal`;
- `calls[2]`: вход `{"days":"7"}` и ошибка `int_type`;
- `assertions: "PASS"`: программная проверка результата и двух ошибок.

Работа с временной базой доказывает сценарий с непустым результатом. В [output/opencode-demo.json](output/opencode-demo.json) отдельно сохранён вызов моделью по рабочей базе с пустым результатом и корректный отказ на `-1`.

## Hook: положительный и отрицательный результат

Команда: `make hook-demo`. Скрипт создаёт временную копию проекта и вызывает тот же обработчик, который экспортирует plugin.

В [output/hook-handler-demo.json](output/hook-handler-demo.json):

- `pass`: ответ после `edit`, содержащий `[AUTO CHECK PASS]` и полный вывод runner;
- `fail`: ответ после `apply_patch`, содержащий `[AUTO CHECK FAIL]` и JavaScript `SyntaxError` после вставки `const broken = ;`;
- `readSkipped: true`: обычное чтение файла не запускает проверку;
- `assertions: "PASS"`: скрипт проверил наличие нужных маркеров в ответах.

Сломан только файл во временной копии; рабочий `index.html` не менялся. Эта запись подтверждает положительный и отрицательный сценарии обработчика. Автоматический вызов самим OpenCode подтверждён отдельной успешной сессией ниже.

### Реальная правка через OpenCode и возврат результата модели

Команда: `python3 scripts/demo_agent.py --hook-only`. Модель: `vsellm/anthropic/claude-sonnet-5.5`, агент `hook-proof`. Собственные MCP и shell в этой короткой сессии отключены, разрешены чтение README/AGENTS и изменение README.

В [output/opencode-hook-demo.json](output/opencode-hook-demo.json) сохранены:

- `exit_code: 0`;
- событие `tool_use` для `read` и затем `edit` со статусом `completed`;
- точная правка в `input.oldString` / `input.newString` и diff в metadata;
- `state.output` события `edit`: `Edit applied successfully`, `[AUTO CHECK PASS]`, семь результатов `ok` и итог `OK`;
- последующее событие `text`: модель сообщает **«Статус AUTO CHECK: PASS»** и **«Тесты логики: 7 из 7 прошли»**.

В [output/hooks.jsonl](output/hooks.jsonl) есть запись с тем же `callID`, `tool: "edit"`, `status: "PASS"` и выводом runner. Следовательно, проверка была запущена plugin после правки; отдельную команду проверки модель не вызывала. Подтверждены и автоматический запуск, и доставка результата агенту.
