# Разбор выбранных skills

## Playwright

Skill из [openai/skills](https://github.com/openai/skills/tree/main/skills/.curated/playwright) задаёт порядок проверки интерфейса: открыть страницу, получить snapshot, найти элементы и выполнить действия. Скрипт `scripts/playwright_cli.sh` запускает CLI через `npx`, поэтому отдельная глобальная установка не нужна, а подробные команды вынесены в `references/`. Snapshot нужен для актуальных ссылок на элементы: после изменения страницы старые ссылки могут стать недействительными. При запуске проверены добавление задачи, поиск, отметка выполнения, фильтр готовых задач, сохранение статуса после перезагрузки и удаление тестовой задачи; подтверждения лежат в `output/playwright/`.

В исходной инструкции приведён путь для глобальной установки. В этом проекте wrapper запускается по проектному пути: `bash .agents/skills/playwright/scripts/playwright_cli.sh --session=practice4 …`.

## Context7 MCP

Skill из [upstash/context7](https://github.com/upstash/context7/tree/master/skills/context7-mcp) описывает два шага: найти ID библиотеки через `resolve-library-id`, затем получить нужный раздел через `query-docs`. Сам skill не скачивает документацию: эту работу выполняет подключённый MCP, а инструкция помогает агенту сформулировать запрос и выбрать источник. Проверка вернула документацию официального Python SDK MCP, а запросы и ответы сохранены в `output/context7-demo.json`. Ответ по основной ветке уже содержит примеры нового `MCPServer`, поэтому для установленного SDK 1.30.0 с `FastMCP` необходимо учитывать версию и сверяться с установленным пакетом; свежая документация может относиться к другой версии API.

## Зачем выбраны

Playwright проверяет поведение реального браузера, включая формы и сохранение данных. Context7 помогает при использовании незнакомого API библиотеки. Собственный MCP отвечает на вопросы о сроках по фактическим данным трекера, а короткий offline runner быстро находит ошибки синтаксиса и логики после правок.
