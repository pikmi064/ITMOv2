# Feature Specification: Редактирование учебной задачи

**Feature**: 001-edit-task | **Created**: 2026-10-28 | **Status**: Ready for implementation
**Input**: улучшить существующий трекер «После пары» одной фичей через две команды.

## User Scenarios & Testing

### User Story 1 — Исправить задачу (Priority: P1)
Студент меняет название, предмет и срок без удаления записи и потери статуса.
**Independent Test**: создать и выполнить задачу, изменить все три поля, перезагрузить страницу и сервер; id/done и новые данные сохранены.
**Acceptance Scenarios**:
1. Given существующая задача, When сохранены три допустимых поля, Then обновляется одна запись с прежним id/done.
2. Given заполненные предмет/срок, When сохранены пустые значения, Then оба очищены.

### User Story 2 — Исправить ошибку или отменить (Priority: P1)
**Independent Test**: отмена не пишет данные; 400/404/сеть сохраняют draft.
**Acceptance Scenarios**:
1. Given открытый редактор, When Отмена/Escape, Then записи нет.
2. Given неверный ввод, When сохранить, Then понятная ошибка без частичной записи.
3. Given 200 PUT и отказ GET, Then сообщение подтверждает сохранение и объясняет отказ обновления списка.

### User Story 3 — Продолжить работу со списком (Priority: P2)
**Independent Test**: поиск и фильтр не сбрасываются; создание, выполнение/возврат, удаление работают.

### Edge Cases
Длины 160/80 и 161/81, пустое название, невозможная/високосная дата, отсутствующий и огромный id, неверный JSON/UTF-8, неизвестные поля, повторный PUT, SQL/HTML-подобный текст, выполненная задача, задача исчезла из выборки.

## Requirements
### Functional Requirements
- FR-001: редактировать title/subject/deadline видимой задачи в одном доступном dialog.
- FR-002: сохранять id/done и нормализованные строки; не мигрировать базу.
- FR-003: строго валидировать поля/тело/id, ошибки JSON 400/404, никаких частичных записей.
- FR-004: отмена без запроса, ошибка без потери draft, блокировка повторного запроса.
- FR-005: отличать отказ сохранения от отказа обновления списка после 200 PUT.
- FR-006: сохранить старые действия, фильтр/поиск и серверную сортировку после успешного GET.
- FR-007: клавиатура/фокус/role=alert; безопасный текст; 375px без переполнения.
### Key Entities
Task: id, title, subject, deadline, done. Редактируемы только три строковых поля.

## Success Criteria
### Measurable Outcomes
- SC-001: все AC1–AC5 контракта подтверждены HTTP и browser тестами.
- SC-002: данные сохраняются после нового процесса сервера на той же временной базе.
- SC-003: независимый агент повторяет проверки и не находит неустранённых существенных дефектов.

## Assumptions
Два локальных клиента: last-write-wins, без версий/409. Все решения по поручению пользователя принимает агент. Подробные UI/logic требования: ui.md и logic.md; общий договор: contracts/api.md. Исходные несогласованные версии: ../before/.
