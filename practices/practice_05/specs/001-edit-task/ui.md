# Согласованная UI-спецификация: редактирование задачи

Дата: 2026-10-28. Автор: отдельный агент «Команда UI». Статус: согласована с контрактом v1.0 до реализации. Основание: исходные `../before/ui.md`, `../before/logic.md` и [общий контракт](contracts/api.md). Решения поручены пользователем основному агенту; ручная приёмка человеком не заявляется.

## Цель и пользовательские истории

Студент исправляет название, предмет или срок существующей задачи, сохраняя её id и done. Операция работает для открытых и выполненных задач.

### US-UI-1 / AC1 (P1): сохранить исправление

Given задача видима в списке, When нажата её кнопка «Изменить», Then открывается один native dialog с текущими title/subject/deadline, подписанными полями и фокусом в title. id/done недоступны для изменения.

Given допустимый черновик, When нажато «Сохранить» или Enter, Then отправлен один PUT из контракта. Во время запроса поля, повторное сохранение, отмена, закрытие и Escape блокируются. После 200 локальная запись заменяется полной записью из ответа; диалог закрывается, затем GET восстанавливает серверную сортировку. Новые данные сохраняются после reload и перезапуска сервера, id/done прежние.

### US-UI-2 / AC2 (P1): очистка и границы

Given заполнены предмет и срок, When их поля очищены и форма сохранена, Then UI отправляет для них пустые строки и после reload отображает отсутствие значений.

Given пробельное название, название длиннее 160 символов, предмет длиннее 80 или неверная дата, When выполняется сохранение, Then пользователь получает понятную ошибку, черновик остаётся, данные не меняются. Длины 160/80 допустимы после strip на сервере. UI не обрезает данные и не вводит более узкий лимит UTF-16: сервер измеряет символы Python; если нужна клиентская проверка, она должна соответствовать этому правилу. Прошлая действительная дата допустима.

### US-UI-3 / AC3 (P1): отмена и отказ

Given есть несохранённые изменения и запрос не выполняется, When нажата «Отмена» или Escape, Then диалог закрывается без PUT и изменений данных. Фокус возвращается новой кнопке той же задачи, а при её отсутствии — поиску.

Given PUT вернул 400/404 или сеть оборвалась, When показана ошибка, Then диалог и введённые значения сохраняются, ошибка имеет role=alert; можно исправить/повторить/отменить. При 404 копия задачи автоматически не создаётся. При потере ответа результат записи может быть неизвестен: повторный PUT с теми же значениями допустим и идемпотентен.

Given PUT вернул 200, а последующий GET завершился ошибкой, When UI завершает обработку, Then подтверждённая локальная запись остаётся, диалог закрыт, показано «Задача сохранена, но список не обновлён». Этот случай не объявляется неудачным сохранением.

### US-UI-4 / AC4 (P2): сохранить прежний сценарий

Given установлен фильтр/поиск, When сохранена правка, Then строка поиска и фильтр сохраняются; статистика и просрочка пересчитываются по актуальным данным. Задача может исчезнуть из выборки после изменения названия, предмета или срока. Это штатно; фокус переходит поиску, если кнопка больше не видима.

Given обновлённая система, When студент создаёт, выполняет/возвращает, удаляет задачи или использует поиск и фильтры, Then назначение и семантика этих действий сохраняются. Состояния пустого списка и отсутствия совпадений остаются различимыми.

## Интерфейс и доступность / AC5

- UI-FR-01: каждая видимая задача имеет кнопку «Изменить» с доступным именем, содержащим название задачи.
- UI-FR-02: одновременно открыт не более чем один native dialog; title/subject/deadline имеют видимые подписи, кнопки — понятные имена. Используется модальное поведение showModal, клавиатурный фокус остаётся внутри.
- UI-FR-03: состояния closed → editing → saving → closed; при отказе saving → editing с сообщением ошибки и сохранённым draft. Повторная отправка не создаёт параллельных PUT.
- UI-FR-04: Tab, Enter и Escape работают согласно состоянию; после закрытия фокус восстанавливается по правилу US-UI-3.
- UI-FR-05: пользовательские данные присваиваются через textContent/value, без интерпретации HTML. Строка с тегами остаётся текстом.
- UI-FR-06: при ширине 375 px нет горизонтальной прокрутки, пересечения кнопок и полей.

## Принятый договор с логикой

| Вопрос исходного draft | Согласованное решение |
|---|---|
| Метод | PUT /api/tasks/{id}; существующий PATCH остаётся операцией done |
| Тело | Ровно три обязательных строковых ключа title/subject/deadline, без id/done; optional очищаются через пустую строку |
| Валидация | title.strip 1–160, subject.strip 0–80; дата пустая или действительная YYYY-MM-DD без внешних пробелов; UI не обрезает данные |
| Успех | 200 с полной записью id/title/subject/deadline/done; id/done неизменны |
| Ошибки | 400 для тела/полей, 404 для маршрута/id или отсутствующей записи; JSON {error: string}; draft сохраняется |
| Частичный успех UI | 200 PUT подтверждает запись; локальное обновление перед GET; отдельное сообщение при GET fail |
| Конкурентность | Последнее сохранение побеждает, версий и HTTP 409 нет |

## Границы и проверяемость

Не входят undo, история правок, аккаунты, синхронизация, массовое редактирование и обнаружение конфликтов. Код практики 4 остаётся исходным snapshot; тесты и демонстрации используют отдельную временную SQLite без пользовательских данных.

Сквозная проверка: изменить все поля у выполненной задачи, проверить id/done, reload и restart; очистить optional; отменить; получить 400/404/сетевую ошибку с сохранённым draft; отдельно смоделировать PUT success + GET fail; проверить фильтр/поиск, клавиатуру, безопасный текст и 375 px. Граничные значения API проверяются интеграционно; одних скриншотов недостаточно.

Открытых вопросов между UI draft и контрактом v1.0 не осталось. Фактическая реализация и независимая приёмка ещё предстоят.
