# После пары — Конституция

## Core Principles
### I. Спецификации раньше кода
Две независимые спеки и общий контракт MUST быть зафиксированы до реализации. Изменение поведения MUST сначала попадать в контракт.
### II. Совместимость
Старые операции MUST проходить регрессию. Редактирование MUST сохранять id/done; миграции и новый framework приложения не нужны.
### III. Проверяемость
Ошибки MUST проверяться HTTP-тестами, пользовательские сценарии браузером. Результат MUST включать команду, ожидание и факт; требуется независимое ревью.
### IV. Данные
Тесты MUST использовать временные базы. Пользовательские задачи и секреты MUST NOT попадать в Git.
### V. Решения
Пользователь поручил все решения основному агенту. Артефакты MUST отличать решения агента от действий человека; выдумывать ручную приёмку запрещено.

## Quality Gates
До кода: baseline, две спеки, контракт, план и отдельный коммит. Перед PR: тесты, браузер, субагент, инструкция защиты.

## Development Workflow
Specify → clarify между командами → plan → tasks → implement → converge → независимое ревью → PR. Работа внутри practices/practice_05.

## Governance
Изменения обосновываются и версионируются: MAJOR меняет принцип, MINOR добавляет, PATCH уточняет. Ревью сверяет требования, реализацию и доказательства.
