# Сверка спецификаций: команда UI

Дата: 2026-10-28 (Europe/Moscow). Роль: отдельный агент «Команда UI». Это запись реальной сверки документов агентом, не протокол ручной приёмки человеком.

Прочитаны:

- `specs/before/ui.md`: собственный независимый исходный draft;
- `specs/before/logic.md`: независимое предложение команды логики;
- `specs/001-edit-task/contracts/api.md`: общий контракт v1.0, решения основного агента по поручению пользователя.

Результат сохранён в `specs/001-edit-task/ui.md` до изменений реализации. Исходные draft не изменены.

## Что сверено и решено

1. Обе команды предлагали отдельный PUT. Принят PUT с тремя обязательными полями; PATCH done не меняется.
2. Сверены поля и типы запроса/ответа, очистка пустой строкой, 200 с полной записью и неизменяемость id/done. Неизвестные поля отклоняются.
3. Приняты единые границы: нормализация title/subject на сервере, длины Python 160/80, каноническая дата, прошлые даты допустимы. UI не должен молча обрезать значения или вводить иной лимит UTF-16.
4. Сверены ошибки 400/404 и отсутствие частичной записи. UI сохраняет draft и даёт повтор/отмену; 404 не создаёт новую задачу.
5. Закрыт выявленный UI риск: после 200 PUT запись считается сохранённой независимо от GET. Сначала локальное обновление из ответа, затем GET; его ошибка имеет отдельное сообщение.
6. Приняты last-write-wins и безопасный повтор PUT после потери ответа. Обнаружение конфликтов вне границ.
7. Уточнены native dialog, блокировка отмены/Escape во время запроса и возврат фокуса кнопке задачи либо поиску после её исчезновения из выборки.
8. Сверены сохранение поиска/фильтра, пересчёт счётчиков/просрочки, серверный порядок после GET, прежние CRUD-действия и тесты на отдельной базе.

Оставшихся несогласованностей с контрактом v1.0 не обнаружено. Реализация не проверялась и в этой задаче не менялась; соответствие кода должно подтверждаться последующими тестами и независимым review.
