# ДЗ6: что сдаём и как защищать

## Что за задание

В актуальной практике 6 нужно исследовать намеренно уязвимый Mini Shop, построить модель угроз, доказать атаки, исправить сервис и повторить проверки. В общей программе курса ещё встречается прежняя тема про coverage/бенчмарки; здесь выполнено фактическое задание из `practices/practice_06/README.md`, с таблицей на 10 баллов.

| Требование | Баллы | Где смотреть |
|---|---:|---|
| Модель угроз | 2 | `THREAT_MODEL.md`, схема Mermaid, активы, границы, STRIDE |

Это соответствие критериям, а не обещание решения преподавателя. Дополнительные баллы можно аргументировать воспроизводимым сценарием парного LLM-эксперимента, тестами неоднозначного HTTP framing и CI, но их начисление решает преподаватель.

## Где лежит результат

Вся работа — в `practices/practice_06/`. `lab/service.py` — исправленный сервис, `lab/sandbox.py` — неизменная физическая граница. `lab/test_service.py` и `lab/test_http.py` — исходные тесты. `lab/test_security.py` — добавленные HTTP-регрессии безопасности. `scripts/experiment.py` — автоматизированный сценарий атак и запросов реальной модели. `evidence/` — фактические ответы и журналы; `REVIEW.md` — независимая проверка субагентом. `LLM_RESULTS.md` объясняет, что реально ответила модель и что выполнил сервер.

Корневой `.github/workflows/practice06.yml` запускает тесты на Python 3.10 и 3.13. Тестам не нужны pip-пакеты, ключи или LLM. OpenCode нужен только для повторения модельного опыта.

## Что показать на защите за 5–7 минут

1. Открой `README.md` практики с критериями, затем Mermaid в `THREAT_MODEL.md`. Объясни четыре границы: HTTP → серверная сессия; контекст → LLM; решение LLM → исполнитель; логическая авторизация файлов внутри физического sandbox.
2. Открой `REPORT_01.md` и `evidence/before/attacks.json`. Покажи три ясных примера: SQL `1 OR 1=1` раскрывает чужие строки; `X-Role: staff` даёт экспорт; `delete_tree(.)` уничтожает только учебные файлы (`files_exist_after: false`).
3. Открой `lab/service.py`. Покажи auth перед закрытыми маршрутами, SQL-параметры, цену `self.products[product]` и allowlist в `/assistant/execute`.
4. Выполни `make step6`. Покажи, что свои данные и действия staff работают, а не только ответы 403. В `evidence/after/attacks.json` сравни те же URL, в `forced-delete.json` покажи 403 и сохранённые файлы.
5. Открой `LLM_RESULTS.md`, пару `normal-model.txt` / `injected-model.txt` и соответствующие JSON-результаты. Раздели ответ модели и полномочия исполнителя. В сохранённых запусках модель недоступна из-за 401/квоты: финального ответа нет, поведение модели не установлено. Не называй timeout отказом модели. После повторения на доступном провайдере можно обсуждать её фактическое решение.
6. Покажи кастомный prompt судьи, `REVIEW.md`, PR и CI. Заверши ограничениями: четыре пробы не доказывают универсальную защиту модели; loopback-стенд не готов к production.

## Ручная демонстрация HTTP

В другом терминале (нужен только Python из stdlib):

```python
import json
from urllib.request import Request, urlopen
from urllib.error import HTTPError

base = 'http://127.0.0.1:8066'
def call(path, data=None, token=None, role=None):
    headers = {'Content-Type': 'application/json'}
    if token: headers['X-Token'] = token
    if role: headers['X-Role'] = role
    req = Request(base + path, data=json.dumps(data).encode() if data is not None else None, headers=headers)
    try:
        response = urlopen(req)
    except HTTPError as exc:
        response = exc
    with response:
        result = json.loads(response.read())
        print(response.status, result)
        return result

alice = call('/login', {'username': 'alice', 'password': 'learn-alice'})['token']
call('/profile?id=1', token=alice)                  # 200, Alice
call('/profile?id=2', token=alice)                  # 403
call('/admin/export', token=alice, role='staff')    # 403
call('/orders', {'product': 'chair', 'price': -1}, alice)  # 201, цена 5000
call('/assistant/execute', {'decision': {'tool': 'delete_tree', 'arguments': {'path': '.'}}}, alice)  # 403
call('/files', token=alice)                        # 200, чек сохранился
```

`--baseline` извлекает исходник из pinned course commit, не переключает ветку и не меняет исправленный код. Чтобы не перезаписать сдаваемые доказательства, здесь используются `/tmp/shop-*`.

## Возможные вопросы

**Почему prompt не является защитой?** Модель может ошибиться или выполнить инструкцию из отзыва. Поэтому JSON модели считается недоверенным вводом, а сервер проверяет конкретный инструмент, роль и точный путь независимо от текста.

**Зачем два уровня файловой защиты?** Sandbox уже защищал ОС от выхода за временный каталог. Он не запрещал Alice читать Bob и `private` внутри него. Добавлена проверка владельца и фиксированного имени чека.

**Почему price не проверяется на положительность?** Любая цена клиента игнорируется. Источник цены — каталог сервера, источник владельца — сессия. Нельзя купить chair за 1 даже с «положительным» значением.

**Почему staff не может удалять через AI?** Полезный сценарий помощника — свой чек. Административный экспорт остаётся отдельным защищённым маршрутом. Избыточные инструменты удалены из исполнителя, а не спрятаны в промпте.

**Исправлены ли абсолютно все риски?** Подтверждённые атаки закрыты регрессиями; ограничения локального HTTP-сервера, учебных паролей, аудита в памяти и отзыва токенов явно перечислены. Гарантию отсутствия любых других ошибок тесты не дают.
