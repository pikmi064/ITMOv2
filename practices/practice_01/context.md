## Context Pack для первого рабочего сценария

### Факты и правила

- Задача помощника: для одного PR получает diff и возвращает (1) краткое `summary` изменения, (2) не больше трёх рисков с `file`, `line`, `evidence`, (3) список `checks` — что запустить, чтобы проверить риски ([`README.md`, «Задача помощника»](README.md#задача-помощника)).
- `SEC-1`: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи.
- `API-1`: diff длиннее 20 000 символов отклоняется с HTTP 413.
- `REL-1`: внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ (не голый 500).
- `QA-1`: риск включается в ответ, только если он подтверждён строкой diff или правилом репозитория — нельзя придумывать риски.

### Формат входа и результата

- Вход: один diff (`TRAINING_PR.diff`), без дополнительного текста от человека во время запуска.
- `OUT-1`: ответ содержит `summary` (строка), массив `risks` (максимум 3 элемента, поля `file`, `line`, `evidence`, `risk`) и массив `checks`.

### Ограничения и запрещённые действия

- `SCOPE-1`: сервис только советует; не пишет код и не выполняет действия в GitHub (approve/merge запрещены).
- `OBS-1`: в лог пишутся только `request_id`, длительность и статус; содержимое diff и ответа модели не логируется.
- Не относится к этому PR и не переносится в Context Pack: правило про `snake_case` для таблиц БД и правило про i18n frontend-строк — в diff нет ни БД, ни frontend.

### Хороший пример

Эталон формата комментария из [`README.md`, раздел «Примеры комментария»](README.md#примеры-комментария) (файл и строка — иллюстрация, не описывают реальный код репозитория):

```text
app/review_service.py:16 — diff отправляется во внешний LLM без удаления секретов,
что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться,
что в prompt осталось [REDACTED].
```

### Плохой пример

```text
Код можно улучшить. Добавьте тесты и обработку ошибок.
```

### Что пока неизвестно

- Как именно будет выглядеть формат ответа внешнего LLM до приведения к `OUT-1` (структурированный JSON или произвольный текст) — зависит от выбранного провайдера, пока не выбран.
- Реализован ли уже редактор секретов (`SEC-1`) в первом инкременте или его нужно добавить — в примере [`TRAINING_PR.diff`](TRAINING_PR.diff) такой логики нет (см. `adr.md`, главный риск).
- Реальный источник diff в проде (webhook GitHub, ручная вставка) — в рамках практики используется только пример [`TRAINING_PR.diff`](TRAINING_PR.diff).

## Как использовали AI

- Для чего: baseline-ревью `TRAINING_PR.diff` без Context Pack, чтобы увидеть, какие факты и правила модель додумывает сама и что она не может подтвердить без правил репозитория.
- Тип промпта: zero-shot.
- Строка в [`prompts.md`](prompts.md): P1-01.
- Что проверили и исправили сами: убрал из списка проблем замечание об «отсутствии тестов» (в задаче это не было заявлено как требование) и замечание про оформление `Protocol.generate` (не относится к рискам PR, тратит бюджет ответа); неоднозначные технические пункты сверил с ответом gemini 3.1 pro.
