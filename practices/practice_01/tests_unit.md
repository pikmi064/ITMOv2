# Unit-проверки

Изолированные проверки логики `ReviewService` и валидации входа. Внешний LLM подменяется заглушкой (`FakeLLM`), сеть не используется.

| Требование или правило | Что проверяем изолированно | Вход | Ожидаемый результат | Evidence |
|---|---|---|---|---|
| `SEC-1` | Редактор секретов вырезает токены/пароли/приватные ключи до сборки prompt | `diff` со строкой `+AWS_SECRET_ACCESS_KEY=AKIAIOSFODNN7EXAMPLE` | В `prompt`, переданном в `llm.generate`, нет исходного значения, стоит `[REDACTED]` | В [`TRAINING_PR.diff`](TRAINING_PR.diff) редактора нет: `app/review_service.py:14` собирает `prompt = f"Review this pull request and find problems:\n{diff}"` — тест падает на текущей реализации |
| `API-1` | Валидатор длины diff отклоняет вход >20 000 символов до вызова LLM | `diff` длиной 20 001 символ | Исключение/ошибка валидации с кодом 413; `llm.generate` не вызван (счётчик вызовов заглушки = 0) | `app/api.py:8-10` вызывает `review_service.review(payload["diff"])` без проверки длины |
| `REL-1` | Вызов LLM обёрнут timeout 10 с и ошибка превращается в контролируемый ответ | `FakeLLM.generate` бросает `TimeoutError` | `ReviewService.review` возвращает контролируемый результат (или доменную ошибку), а не пробрасывает голое исключение наружу | `app/review_service.py:15` — `answer = self.llm.generate(prompt)` без `try/except` и без timeout |
| `OUT-1` | Ответ приводится к структуре `summary`/`risks`/`checks` | `FakeLLM` возвращает валидный ответ модели | Результат — словарь с ключами `summary` (str), `risks` (list, ≤3), `checks` (list); у каждого риска есть `file`, `line`, `evidence`, `risk` | `app/review_service.py:16` возвращает `{"comment": answer}` — контракт `OUT-1` не выполняется |
| `OUT-1` | Лимит числа рисков соблюдается при «болтливой» модели | `FakeLLM` возвращает 5 рисков | В результате ровно 3 риска (лишние отброшены), ошибки нет | Правило `OUT-1` из [`context.md`](context.md): максимум три элемента в `risks` |
| `QA-1` | Риск без `file`/`line`/`evidence` не попадает в ответ | `FakeLLM` возвращает риск без `line` и без цитаты | Такой риск отфильтрован; при отсутствии подтверждённых рисков `risks == []` | Правило `QA-1`; сравнение baseline `runs/P1-01_out.txt` (пункты «нет тестов», «стиль») с `runs/P1-02_out.txt` |
| `OBS-1` | В лог не попадает содержимое diff и ответа модели | `diff` с уникальным маркером `MARKER_UNIQUE_42`, перехват логов | В записях лога есть `request_id`, длительность, статус; маркера и текста ответа модели нет | Правило `OBS-1` из [`context.md`](context.md) |

## Как использовали AI

- Для чего: не использовал AI для составления таблицы — кейсы выведены вручную из правил Context Pack (`SEC-1`, `API-1`, `REL-1`, `OUT-1`, `QA-1`, `OBS-1`) и строк [`TRAINING_PR.diff`](TRAINING_PR.diff).
- Тип промпта: —
- Строка в [`prompts.md`](prompts.md): P1-02 (риски `SEC-1`, `API-1`, `REL-1` из ответа второго запуска стали источником первых трёх кейсов)
- Что проверили и исправили сами: сверил номера строк (`app/review_service.py:14-16`, `app/api.py:8-10`) с diff вручную; отбросил кейсы, которые не привязаны ни к правилу, ни к строке diff, чтобы не повторить ошибку baseline (`QA-1`).
