# Нагрузочные проверки

Нагрузочное тестирование в первом инкременте выполняется в минимальном объёме: цель — не пропускная способность сервиса, а проверка того, что правила `API-1` и `REL-1` держатся, когда запросы идут не по одному. Ответ сервиса ограничен временем внешнего LLM-вызова (10 секунд, `REL-1`), поэтому измеряем в первую очередь поведение под очередью, а не RPS.

| Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Evidence |
|---|---|---|---|---|
| Базовый профиль ревью | 5 параллельных запросов `POST /api/reviews`, diff ~1 000 символов, 5 минут | p95 времени ответа ≤ 12 с (10 с `REL-1` + накладные расходы), ошибок 5xx = 0 | p50/p95 времени ответа, доля 5xx, число обращений к LLM | `REL-1` из [`context.md`](context.md); синхронный вызов в `app/review_service.py:15` |
| Отказ по длине без нагрузки на LLM (`API-1`) | 20 параллельных запросов с diff 20 001 символ, 2 минуты | 100% ответов — HTTP 413; вызовов LLM = 0 | Код ответа, счётчик вызовов LLM-заглушки | `API-1`; `app/api.py:8-10` вызывает сервис без проверки длины |
| Медленный LLM-провайдер (`REL-1`) | 10 параллельных запросов, заглушка LLM отвечает 11 секунд, 3 минуты | Все запросы завершаются контролируемым ответом за ≤ 12 с; зависших соединений и голых 500 нет | Время до ответа, код ответа, число незакрытых соединений | `REL-1`; `app/review_service.py:15` без timeout и `try/except` |
| Граница лимита diff | 10 параллельных запросов с diff 19 999 символов, 2 минуты | Ответ 200 по контракту `OUT-1`; p95 ≤ 12 с; ошибок 5xx = 0 | Код ответа, p95, структура тела ответа | `API-1` (граница 20 000), `OUT-1` |

Когда потребуется полноценное нагрузочное тестирование: после инкремента 3, если сервис подключается к реальному GitHub-webhook (поток PR перестаёт быть ручным) или если появляется больше одного одновременного пользователя-ревьюера с SLA на время ответа. До этого момента предел определяется внешним LLM-провайдером, а не кодом сервиса.

## Как использовали AI

- Для чего: не использовал AI — профили нагрузки выведены вручную из `REL-1` (timeout 10 с) и `API-1` (лимит 20 000 символов); никаких значений RPS «по умолчанию» не переносил.
- Тип промпта: —
- Строка в [`prompts.md`](prompts.md): P1-02 (риски `API-1` и `REL-1` из второго запуска задали два из четырёх сценариев)
- Что проверили и исправили сами: убрал сценарии с придуманными целевыми RPS и SLA — таких требований нет ни в [`README.md`](README.md#учебный-кейс-ai-помощник-ревьюера-pr), ни в Context Pack; вместо них оставил пределы, выводимые из известных правил, и назвал условие, после которого нужен полноценный load test.
