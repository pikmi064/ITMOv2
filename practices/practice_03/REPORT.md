# Отчёт: практика 3, локальные модели

## Окружение

| Параметр | Значение |
|---|---|
| ОС | macOS 27.0.1 |
| CPU / GPU | Apple M4 (GPU встроенный, память унифицированная) |
| RAM | 16 GB (общая для CPU и GPU) |
| Свободный диск | 219 GB |
| Ollama | 0.40.0 (установлен через Homebrew), сервер запущен с `OLLAMA_NO_CLOUD=1` |
| OpenCode | 1.18.31 |
| Python | 3.14.5 (нужен 3.10+, зависимости только стандартная библиотека) |

**Модель:** `qwen3.5:4b`, разработчик Alibaba (Qwen), семейство Qwen3.5.
- ID в `ollama list`: `7f3251fa6878`, размер на диске 4.0 GB.
- Архитектура `qwen3_5`, 4.5B параметров, квантизация **nvfp4**, лицензия Apache 2.0, источник: каталог Ollama (`ollama pull qwen3.5:4b`).
- Возможности по `ollama show`: completion, vision, thinking, **tools**.
- Родной контекст модели 262144 токена.

**Профили на одних и тех же весах** (лишних копий весов на диске нет):

| Имя | Файл | Контекст | Назначение |
|---|---|---|---|
| `itmo-local` | `lab/Modelfile` | 4096 | прямой чат / API, со встроенным SYSTEM |
| `itmo-agent` | `lab/Modelfile.agent` | 65536 | OpenCode, без SYSTEM (инструкции даёт агент) |

**Фактический контекст и размещение** (`ollama ps`):

| Профиль | Память | Процессор | Контекст | Runner |
|---|---|---|---|---|
| `qwen3.5:4b` / `itmo-local` | 4.4 GB | 100% GPU | 4096 | mlx |
| `itmo-agent` | 6.0 GB | 100% GPU | 65536 | mlx |

Рост с 4.4 до 6.0 GB даёт KV-cache при большом контексте, веса те же.

**Почему такая конфигурация.** Для 16 GB рекомендован `qwen3.5:4b`. Он целиком помещается в унифицированную память и считается на GPU. Контекст 64k нужен агенту, потому что его системный prompt и результаты чтения файлов длинные. Остаётся запас: после запуска 64k профиля свободной памяти было около 37%. Меньшие модели (0.8B/2B) не пробовались, так как 4B работает без проблем с памятью.

## Воспроизведение

```bash
brew install ollama
OLLAMA_NO_CLOUD=1 ollama serve            # отдельным процессом
ollama pull qwen3.5:4b
cd practices/practice_03/lab
ollama create itmo-local -f Modelfile
ollama create itmo-agent -f Modelfile.agent
make test                                 # 3 теста, OK

# один вопрос (повторить для каждого из QUESTIONS.md в новой сессии)
opencode run --dir demo --agent local-guide --model ollama/itmo-agent --format json \
  "Как запустить тесты? Укажи файл-источник." > results/q1.jsonl
```

- **Локальный endpoint:** `http://localhost:11434/v1`. В `demo/` `opencode models` выдаёт единственную модель `ollama/itmo-agent`.
- **Веса скачаны локально** (`ollama list`, `~/.ollama/models`).
- **Работа без сети после подготовки не проверялась.** Облачные функции Ollama отключены переменной окружения, облачный провайдер в `demo/` не разрешён через `enabled_providers`. Но глобальный конфиг OpenCode пользователя содержит облачного провайдера: он остаётся в слитой конфигурации, хотя его модели в `demo/` недоступны.
- Работа выполнялась на одном компьютере, без партнёра.

## Ограничения и обнаруженные ошибки

1. **Угадывание стека.** В Q1, Q2, Q3, Q5 модель сначала искала `*.js`, `*.ts`, `package.json`, `.github`, хотя проект на Python. Она подставляет привычные шаблоны вместо того, чтобы сначала посмотреть список файлов.
2. **Верный вывод из неполных данных (Q3).** Модель прочитала только `opencode.json` и заявила, что в каталоге «только конфигурационный файл», хотя там есть `service.py`. «Нет `unsubscribe`» совпало с истиной случайно. На проекте, где функция есть, такой же приём дал бы ложное «нет».
3. **Неточность формулировки (Q1).** Названа команда `make` вместо `make test`.
4. **Выдуманный путь при проверке чтения.** В одном из трёх пробных запусков (до основных вопросов, результаты не сохранены) модель вызвала `read` с несуществующим путём `.../ITMOv2/practice_03/...` без `practices/`, затем ответила, что файл не найден. В двух других запусках путь был верным.
5. **Скорость.** Около 3-4 минут на вопрос, большая часть уходит на обработку длинного системного prompt OpenCode (около 8.9 тысяч символов) и контекста 64k. Для интерактивной работы это медленно.
6. **Память.** 64k контекста добавляет около 1.6 GB к 4.4 GB. На 16 GB это работает, но запас ограничен.
7. **Системный prompt OpenCode нельзя отключить.** Агент без ключа `prompt` и с пустым `prompt` отправляют один и тот же встроенный текст. Свой `prompt` его заменяет.

## Дополнительное исследование (не входит в требования, результаты в репозитории не сохранены)

Проведено на этапе подготовки, на прямых запросах к API (`qwen3.5:4b`, один вопрос «какая CI-система запускает тесты?» по `demo/README.md`). Исходные файлы результатов удалены как лишние, цифры ниже взяты из журнала работы.

**System prompt против его отсутствия.** Без system-сообщения модель признала, что определить CI нельзя, но дальше домысливала («скорее всего вызывает pytest или unittest», упоминание курса Яндекса): 268 токенов, 11.7 с (включая холодную загрузку). С `system.txt` ответила «В предоставленных материалах нет ответа» и дала основание: 71 токен, 3.3 с. Скорость декодирования одинакова, 27.0 и 26.8 токенов/с. Разница по времени идёт от длины ответа.

**Temperature 0.2 и 0.8, seed 42/43/44.** Во всех шести ответах верно «нет ответа», выдуманных CI-систем нет. Высокая temperature ошибок не дала, но на одном вопросе и трёх seed это ничего не доказывает.

| Конфигурация | Медиана wall, с | Медиана токенов/с |
|---|---|---|
| temperature 0.2 | 2.00 | 24.9 |
| temperature 0.8 | 2.31 | 26.3 |
| холодный старт (1 запуск) | 5.16, загрузка весов 1.81 | 25.6 |

Оговорка: это три разных seed на конфигурацию, а не три повтора одного запроса. TTFT не измерялся (ответ не потоковый).

## Вывод

- **Конфигурация, которую оставляю:** `qwen3.5:4b` (nvfp4) с профилем `itmo-agent` (64k) для OpenCode и агентом `local-guide` с `repo-system.txt`; для прямого чата `itmo-local` со встроенным SYSTEM.
- **Что работает:** локальная модель целиком на GPU, OpenCode подключён к `localhost`, агент реально вызывает `glob`, `read`, `grep`. На двух проверочных вопросах (ложная предпосылка и отсутствие данных) выдумок нет.
- **Чему нельзя доверять без проверки:** процессу получения ответа. Верный вывод может быть получен без чтения нужного файла (Q3), поэтому ответы нужно сверять с событиями инструментов.
- **Что осталось непроверенным:** работа полностью без сети; другие модели и квантизации; другие проекты; повторяемость результата на нескольких запусках одного вопроса (каждый вопрос задан по одному разу); влияние `repo-system.txt` на ответы (сравнение с агентом без своего prompt не проводилось).
